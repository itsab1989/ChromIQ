# F-007 A change to an Instrument Limit in Preferences reaches the inspector at once but not the layout panel, the estimate or the next build
Area: layout engine / Preferences (Instrument Limits)
Grade: OBSERVED
Attended: unattended (the Preferences dialog was driven by a timer that asserted its title and pressed its OK)
Type: bug
Severity: high
Expected: Instrument Limits help text: "When you generate a chart, the Create Chart preview measures its actual margins and compares them to the values here". With "Use instrument margins" ticked, the layout panel's margins ARE those values, so after OK the panel, the estimate and the next chart follow the new minimum, and the inspector agrees with them.
Actual: Manual, engine on, i1Pro A4 portrait, instrument margins ticked (panel 38/9/19/26, estimate 525). Preferences > Instrument Limits > i1Pro / A4 Portrait: Top 38 -> 50, ruler 240 -> 200, OK. Settings on disk: T 50, ruler 200 (read back). After OK: panel still 38/9/19/26, estimate still 525. Generate: chart built with Top 39.0 (525, 25 x 21). The inspector then judged that same chart against the new table: red "Top margin 39.0 mm is below the 50 mm instrument minimum", min column 50.0, plus "Strip length 238 mm exceeds the 200 mm instrument ruler". So one screen says: instrument margins in force, and violated. The panel picked up 50 only when the checkbox was toggled off and on later; after the limit was restored to 38 in Preferences the panel then read 50 (one round behind in the other direction).
Why it matters: The Instrument Limits tab is the owner's mechanism for a user's own ruler or jig. Editing it and pressing Generate produces a chart the app immediately flags as unreadable, with the box that promises the fix still ticked. A user will conclude the feature is broken.
Steps to reproduce (click by click): MANUAL, engine on, i1Pro, A4 portrait, tick "Use instrument margins". Open Preferences (gear icon) > Instrument Limits, Instrument i1Pro, Paper A4 Portrait, set Top to 50, press OK. Look at the Margins boxes (still 38). Press Generate Chart. Read the red line under the preview.
Evidence: Screenshots/A4-margins/prefs-i1-A4-T50-ruler200.png (dialog as edited), t01-after-prefs-T50-before-generate.png (panel unchanged), t02-after-prefs-T50-generated.png (red verdict under a 39 mm top), Test Runs/logs/d03b_thresholds_and_stripcap.log (thresholds before/after read from settings; "panel margins after restore: t 50"), d03b_results.json.
Spec or source cited: ui/main_window.py:_open_settings refreshes `_apply_instrument_default_margin`, `_update_patch_count`, `_refresh_manual_command_preview`, `refresh_margin_inspector_settings` after the dialog, but nothing calls the layout panel's `_sync_instr_margins` (ui/dialogs/layout_options_panel.py:2915), which is what copies the table into the four boxes. docs/design/per_target_settings.md section 1.1 makes Preferences the seed; section 4c says an instrument default may set a control the user has not answered, which is exactly this case (the boxes are locked to the table).
Possible solutions (no code): A. After the Preferences dialog closes, re-run the panel's instrument-margin sync (and the estimate) when "Use instrument margins" is ticked. B. Make the panel read the table lazily at Generate and at every estimate instead of copying it into the boxes. C. Also refresh the panel when the table changes for the combo currently selected.
Regression risk if changed: Low-medium; the sync already runs on instrument/paper change and on the checkbox, so running it once more after Preferences is the same code path. Beware the "_saved_margins" restore baseline (user's own margins are remembered when the box is ticked).
Needs owner decision: no
