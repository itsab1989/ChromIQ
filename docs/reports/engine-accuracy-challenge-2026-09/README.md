The evidence behind `docs/dev_profile_engine_accuracy_challenge.md`, copied from
the owner's proof folder so it travels with the branch.

- `orchestrator/` — the plan, the agent briefs, the running fix log, the handover
  and the final report (`07-final-report.md` is the summary to read first).
- `critic/` — the attack on the plan before any code was written.
- `agent-A/` — colour-science findings (21), every number with its command.
- `agent-B/` — on-screen journeys in the real app (33 findings; pictures in
  `screenshots/`, downscaled).
- `reviewer/` — the adversarial review of the fixes (18 items).
- `challenger/` — the independent verification of the final claims.
- `agent-C/`, `agent-D/`, `agent-E/` — the three follow-up items: smoothing
  criterion (negative result), black depth (landed), light inks (referee landed,
  separation diagnosed to the forward model).
- `battery/` — the synthetic battery JSONs and compare logs (the referee).

Every measurement file on the owner's drive was treated as developer test data,
never as ground truth; the synthetic battery, colprof parity and the ICC
specification were the referees.
